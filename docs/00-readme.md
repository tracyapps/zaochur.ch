# The Zao Commons — Planning & Foundations

> **Status:** Draft v0.1 — October 2026 — for community review
> **Where this lives:** These documents will be published in the open at **zaochur.ch** so the whole community can read them, question them, and shape them.

## What this is

Zao's Digital Commons currently lives on Discord. This is the planning home for reimagining it: a Digital Commons that Zao owns, shaped like the church herself — her rooms, her harbors, her rhythms of rest and celebration — and built to keep safe the most vulnerable among us.

This is not a tech project that happens to involve a church. It is a community-care project that happens to need software. Every document here starts from our beliefs, not from features.

## How decisions get made here

Beliefs → Non-Negotiables → Principles → Roadmap & Technology → Decision Log.

If a feature, a vendor, a shortcut, or a deadline conflicts with the non-negotiables, **the feature changes — not the document.** Changing the non-negotiables themselves requires community discernment, not one person's late night.

## How to participate

You don't need to be technical to shape this. In fact, the people we most need to hear from are the ones for whom the current tools hurt most. During Phase 0 there will be listening conversations, open comment periods on every document here, and working groups for care, design, and building. Watch the [Roadmap](06-roadmap.md) for how to join in.

## Folder guide

**Inside the GitHub repository** (`app/` — planning and code together, in the open):

- `docs/` — these planning documents (public-ready; published at zaochur.ch)
- `docs/for-reference/` — source material: the ZAO Bank system design document and a reference screenshot of the games channel. (The saved website pages were reviewed and retired — their brand language and terminology live on in these documents.)
- repo root — the codebase, once we begin building (Phase 1)

**Outside the repository, by design:**

- `branding-design/` — brand and design assets: the image library, large design files, and work-in-progress art that would clutter a code repository. Finished, repo-relevant assets (design tokens, icons) are copied into the repo deliberately — never bulk-synced.
